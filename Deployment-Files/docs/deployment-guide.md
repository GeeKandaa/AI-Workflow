# Deploying the AI plan workflow template

The template is a copy-and-paste package. You copy its contents into a workspace root and run `deploy.ps1`
once. The workspace root holds one project, and each sub-folder is a git worktree of it. The workflow never
manages the root itself; it only manages the worktrees.

## 1. Requirements

- Node.js 18 or newer on `PATH`. The CLI has no dependencies, so there is nothing to install.
- Git.
- Claude Code.
- Windows PowerShell 5.1 or PowerShell 7, to run `deploy.ps1`.

## 2. Copy the package

Copy everything inside the package folder into the workspace root, including hidden items. On Windows, turn on
*View → Hidden items* so that `.claude-template` and `.gitignore` are visible. The workspace root should then
contain:

```
<workspace>/
├─ .claude-template/         commands/ tests/ workflow/ settings.json
├─ CLAUDE.template.md
├─ .gitignore                keeps plans out of git (see step 3)
├─ deploy.ps1
├─ docs/                     project-level documentation
├─ plans/archive/.gitkeep
└─ <worktree-a>/ <worktree-b>/ …   ← if you already have worktrees
```

The workflow files ship as `.claude-template` and `CLAUDE.template.md` so that Claude Code ignores them while
the package is being developed. `deploy.ps1` renames them.

## 3. Run deploy.ps1

From the workspace root:

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy.ps1
```

`-ExecutionPolicy Bypass` is needed because Windows blocks unsigned scripts by default.

The script checks everything, and asks its questions, before it changes anything:

1. **Keep or remove `.gitignore`?** The file stops plans being committed by default by anyone working in a git
   repository that contains the workspace: only `plans/archive/.gitkeep` is tracked. The script suggests **Keep**
   when it finds a `.git` in the workspace root or any folder above it, and **Remove** otherwise. Press Enter to
   accept the suggestion, or answer `k` or `r`.
2. **Continue?** The script lists what it will do and waits for `y`.

It then renames `.claude-template` to `.claude` and `CLAUDE.template.md` to `CLAUDE.md`, keeps or deletes
`.gitignore`, lists the worktrees it found, runs the workflow tests, and deletes itself.

Options:

| Option | Effect |
| --- | --- |
| `-GitIgnore Keep` / `-GitIgnore Remove` | answers the `.gitignore` question without asking |
| `-Yes` | skips both prompts; uses the suggested `.gitignore` answer unless `-GitIgnore` is given |
| `-SkipTests` | skips the test run |

If a previous install exists, see section 8.

## 4. Add your worktrees

Each sub-folder of the workspace root is a git worktree of the project. Create them inside the root, for
example from an existing main checkout:

```bash
git -C main worktree add ../feature-x -b feature-x
```

Each sub-folder that contains a `.git` (a folder or, for a worktree, a file) is discovered automatically and named
after its folder. Plans use that name in `### <worktree>` headings. To use a different name, add it to
`repositories.map` in `.claude/workflow/config.json`, for example `{ "api": "services/api" }`.

The workspace root itself is never managed, because `repositories.includeRoot` is `false` by default.

## 5. Configure

These settings are in `.claude/workflow/config.json`:

- `commit`: the subject regex, line lengths and required trailers for commit messages. Keep
  `.claude/workflow/commit-template.txt` in line with these rules, because the AI uses that file as its
  style guide.
- `archive.allowUnlistedByDefault`: whether uncommitted changes that no plan lists block completion and
  archival.

`.claude/settings.json` denies the human-gate commands (`stage`, `continue`, `cancel`, `rework`,
`archive-begin`) and git writes to the AI. Edit the `permissions` there to loosen or tighten them.

### Generated files

Only the files a plan lists in Files Affected are ever committed, so a plan must list the files its work
regenerates too: lockfiles, generated code, migrations, test snapshots, committed build output. The AI predicts
them while planning from the project's tooling and from `docs/`. To make that reliable, describe in `docs/` which
commands regenerate which files, and which output is committed or ignored.

Anything it misses is caught at `complete`: changes that no plan lists block it, with instructions to add files
the work generated (noted `— generated by <command>`) or explain why they're unrelated. Changes in worktrees the
plan doesn't list at all produce a warning. The AI mentions any generated file `docs/` didn't predict, so you can
document it.

## 6. Verify

Run these from the workspace root.

1. Check worktree discovery. It should list your worktrees, and `root` should not appear.

   ```bash
   node .claude/workflow/plan.mjs repos
   ```

2. Check the UI's view of the plans. It should print JSON with an empty `plans` list.

   ```bash
   node .claude/workflow/plan.mjs status --json
   ```

3. Start Claude Code in the workspace root and ask it to run `node .claude/workflow/plan.mjs stage x`. A
   permission rule should deny it.

To rerun the tests that `deploy.ps1` ran:

```bash
node --test .claude/tests/workflow.test.mjs
```

## 7. Day-to-day use

The plan UI drives the lifecycle. Without it, run the gates in your own terminal and the phase prompts in
Claude Code:

| Step | Gate (you or the UI) | Phase prompt (Claude) |
| --- | --- | --- |
| Write a plan | — | `/plan-new <description>` |
| Answer its questions or change it | — | `/plan-amend <plan> <instructions>` |
| Approve and implement | `plan.mjs stage <plan>` | `/plan-implement <plan>` |
| Approve a deviation | `plan.mjs continue <plan> [--decision "Option 2"]` | `/plan-continue <plan>` |
| Send back with feedback | `plan.mjs rework <plan> --feedback "…"` | `/plan-rework <plan>` |
| Cancel to planning | `plan.mjs cancel <plan>` | `/plan-cancel <plan>` |
| Accept, commit and archive | `plan.mjs archive-begin <plan> [--allow-unlisted \| --manual-commit …]` | `/plan-archive <plan>` |
| Merge plans that must be archived together | `plan.mjs merge <into> <plan…>` (undo: `unmerge <plan>`) | `/plan-merge <into>` |
| See all plans | `plan.mjs status [--json]` | `/plan-status` |

## 8. Upgrading a workspace that runs an older template

1. Check that no archival is running and that no plan is part-way through implementation:

   ```bash
   node .claude/workflow/plan.mjs status
   ```

2. Close Claude Code and the plan UI.
3. Copy the new package into the workspace root, as in section 2, overwriting `deploy.ps1`, `docs/` and
   `.gitignore` if asked.
4. Run `deploy.ps1`. It backs up the old `.claude` to `.claude.old` and the old `CLAUDE.md` to `CLAUDE.md.old`, and
   copies `.claude/settings.local.json` into the new install. It refuses to run if those backups already exist
   or an archival is in progress.
5. If you had customised `config.json`, merge your `commit` and `repositories` settings from
   `.claude.old\workflow\config.json` into the new file by hand.
6. Run the checks in section 6. Existing plans keep working: format changes so far only add optional sections
   (`## Outstanding Questions`). When all
   the checks pass, delete `.claude.old` and `CLAUDE.md.old`.

## 9. Troubleshooting

- **"running scripts is disabled on this system".** Run the script with `-ExecutionPolicy Bypass`, as in
  section 3. If the package came from a download, you can also run `Unblock-File .\deploy.ps1` first.
- **`deploy.ps1` says ".claude-template was not found".** Hidden items were not copied. Copy the package again
  with hidden items visible.
- **`plan.mjs repos` lists nothing.** None of the sub-folders contains a `.git`. Add worktrees (section 4) or
  add them to `repositories.map`.
- **`stage` is refused because of shared files.** Another staged plan lists the same file in the same worktree.
  Complete that plan first, or remove the overlap from one of the plans.
- **A command is refused by the branch check.** The worktree is on a different branch from the one recorded
  when the plan was staged, or its HEAD is detached. Check out the recorded branch (see `branches:` in the plan,
  or `status --json`) and retry, or cancel the plan and stage it again on the new branch.
- **`archive-begin` says another archival holds the lock.** Only one archival runs at a time. Wait for it to
  finish, or run `plan.mjs archive-abort <plan>` for that plan if it was abandoned before committing.
- **`complete` reports changes that no plan lists.** Add them to the plan, or pass `--allow-unlisted` if they
  belong to unrelated work.
- **Rollback after an upgrade.** Close Claude Code, delete `.claude` and `CLAUDE.md`, then rename `.claude.old`
  and `CLAUDE.md.old` back.
